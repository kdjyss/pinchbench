# PC-Sim Skill Benchmark 综合评测报告

**评测框架**: pinchbench + Claude Opus 4.6 手动评分  
**评测任务**: 52 个 PC 模拟器技能任务 (L1-L6)  
**评测日期**: 2026-04-02  
**评分人**: Claude Opus 4.6 (逐条 transcript 人工审阅)

---

## 1. 评测概述

### 1.1 评测目标
评估不同 LLM 在 PC 模拟器环境中作为 AI Agent 的表现，重点考察：
- 能否正确发现和使用 pc-sim 工具
- 能否准确理解用户意图并完成任务
- 回答是否清晰、准确、有用
- 执行效率是否合理

### 1.2 任务分布

| 难度 | 名称 | 任务数 | 描述 |
|------|------|--------|------|
| L1 | 信息查询 | 14 | 单工具查询（天气、电池、联系人等） |
| L2 | 单步操作 | 12 | 单工具写入（创建联系人、设闹钟、付款等） |
| L3 | 同技能多步 | 8 | 同一 skill 内多步操作（录音开始+停止等） |
| L4 | 跨技能协作 | 8 | 多 skill 协调（查联系人+打电话等） |
| L5 | 复杂场景 | 5 | 3-4 个 skill 协调的复杂任务 |
| L6 | 异常处理 | 5 | 错误识别和友好提示 |

### 1.3 评分体系

**双轨评分**:
- **Automated Score** (40%): 自动检查工具调用和回复内容
- **Claude Manual Score** (60%): 人工审阅 transcript 后按 4 维度打分

**Claude 打分维度**:

| 维度 | 权重 | 评估内容 |
|------|------|---------|
| 任务完成度 | 30% | 用户请求是否全部完成，结果是否正确 |
| 工具使用 | 25% | 工具选择是否正确、参数是否准确、有无误用 |
| 回答质量 | 25% | 回复是否清晰、准确、结构化、无编造 |
| 效率 | 20% | 步骤数是否合理、有无冗余/重复调用 |

## 4. 优化效果分析

### 4.1 v1 → v3 进化路径

```
v1 (75.9%) → 删除 BOOTSTRAP.md → v2 (79.6%) → TOOLS.md 优化 → v3 (88.8%)
                  +3.7%                              +9.2%
                                          总提升: +12.9%
```

### 4.2 关键修复任务

| 任务 | v1 | v2 | v3 | 修复原因 |
|------|----|----|-----|---------|
| 查询电池状态 | 0% | 100% | 100% | 删 BOOTSTRAP 后不再编造命令 |
| 查询当前位置 | 0% | 0% | **100%** | TOOLS.md 引导后正确调用工具 |
| 查询室内温度 | 0% | 100% | 100% | 删 BOOTSTRAP 后不再输出乱码 |
| 查询电脑配置 | 0% | 100% | 100% | 不再用系统命令替代 pc-sim |
| 查询明天会议和天气 | 0% | 0% | **100%** | TOOLS.md 引导后正确跨技能调用 |
| 出门前设备配置 | 0% | 100% | 100% | TOOLS.md 引导后完成全部子任务 |
| 播放指定歌曲 | 100%(10步) | 100%(10步) | **100%(3步)** | 效率大幅提升 |

### 4.3 各优化手段的效果

| 优化手段 | 影响 | 效果 |
|---------|------|------|
| 删除 BOOTSTRAP.md | 消除"先自我介绍"的干扰 | +3.7% (v1→v2) |
| TOOLS.md 工具索引 | 引导模型先读 SKILL.md | +9.2% (v2→v3) |
| 精简 IDENTITY.md | 减少 system prompt 噪音 | 包含在 v2 提升中 |

## 5. 典型问题分析

### 5.1 已解决的问题

| 问题 | v1 表现 | v3 表现 |
|------|---------|---------|
| 编造命令(如 pc-battery --status) | 频繁(~20次) | 极少 |
| 被身份设定干扰跑偏 | 有(location) | 已解决 |
| 混淆模拟器与宿主机 | 常见(3个任务) | 大幅减少 |
| 不读 SKILL.md 直接猜 | 几乎所有失败任务 | 多数先读后调用 |

### 5.2 仍存在的问题

| 问题 | 涉及任务 | 说明 |
|------|---------|------|
| processes 用 ps aux | task_35 | 未调用 pc_shell_list_processes |
| install_package 用 pip | task_64 | 未调用 pc_runtime_env |
| calendar_reminder 失败 | task_54 | 用 memory_search 而非 calendar 工具 |
| 部分任务步骤过多 | silent_volume(26步) | 反复猜命令格式 |

### 5.3 小模型 vs 大模型的核心差异

| 能力 | deepseek-chat | Qwen3.5-9B v3 |
|------|-------------|---------------|
| 首次命令准确率 | ~95% | ~70% |
| 读 SKILL.md 后准确率 | 100% | ~95% |
| 跨技能协调 | 完美 | 偶有遗漏 |
| 效率(平均步数) | 2-3步/任务 | 3-5步/任务 |
| 模拟器/真实系统区分 | 完美 | 偶尔混淆 |

## 6. 结论与建议

### 6.1 核心结论

1. **deepseek-chat 表现最优** (98.3%)，几乎完美完成所有任务
2. **Qwen3.5-9B 通过 prompt 优化从 75.9% 提升到 88.8%**，提升 12.9 个百分点
3. **Prompt 工程比模型大小更有效**：4B+TOOLS.md (83.0%) > 9B v1 (75.9%)
4. **TOOLS.md 是最有效的优化手段**，贡献了 +9.2% 的提升
5. **效率是小模型的最大短板**（75.0% vs deepseek 的 91.0%）

### 6.2 优化建议

**对 openclaw 侧**:
- 继续完善 TOOLS.md，增加更多工具使用示例
- 在 CLAUDE.md 中明确"先读 SKILL.md 再执行"的规则
- 精简 IDENTITY.md/SOUL.md 减少小模型的注意力分散

**对 pc-sim 侧**:
- 统一相似工具的命名（memo vs notes, camera vs screenshot）
- 在 SKILL.md 中加入"常见混淆"提示
- 考虑增加 pc_shell_list_processes 的别名支持

**对评测框架**:
- task_27 (volume_check) 的 automated 评分应支持 `pc_volume_get_all_streams` 作为等价工具
- task_35 (processes) 需要更明确的 prompt 引导使用 pc-sim 而非系统命令
- 考虑增加效率相关的 automated 检查（步数上限）
